# 文章配图指南

本文件负责选图、规划、共同检查和资产组织。任务范围与用户要求的优先级见 [主文件](../SKILL.md)；角色、画风和布局由选定的绘图 skill 及本地配置维护。

## 先选职责，再选画法

一张图回答一个主要问题。没有新增关系或证据、只是重复标题的图通常不画；不按章节数量凑图。

| 图要完成的任务 | 默认方式与参考 | 交付资产 |
| --- | --- | --- |
| 正文插图：观点、类比、章节情境和概念隐喻 | `visual-ip-illustrations`，显式指定 Tom（路由 `tom`），见 [Tom 插图配置](tom-illustrations.md) | 原始生成图片、完整提示词 |
| 架构、流程、时序、状态、部署、关系、层级和方案演进等结构说明图 | `baoyu-infographic`，默认 `craft-handmade`，见 [Baoyu 架构图配置](craft-handmade-infographics.md)；涉及真实实现时另核对 [内容规范](engineering-diagrams.md) | 原始生成图片、完整提示词和结构说明 |
| 界面、操作、故障和运行效果 | 真实截图、GIF、日志或 Trace，见下文 | 真实素材及必要标注 |
| 性能、延迟、吞吐等测量比较 | 标准数据绘图工具，见下文 | 数据图及数据、口径 |
| 文章封面 | 按平台比例独立构图，通常使用 `imagegen` | 封面原图及提示词 |

用户指定其他角色、风格或编辑格式时采用其要求。区分依据是图的表达方式：Tom 通过动作和隐喻解释一个观点；Baoyu 用节点、边、分组、层级或时序解释结构。仅因为涉及真实组件、协议或关键文字，不得自动将架构图切回 SVG 路线；应先核对关系，再交给 Baoyu 生成并检查。

只有用户明确要求可编辑 SVG、draw.io、FigJam 等源文件，或要求维护已有此类资产时，才按该交付需要选择相应工具。旧 [sincerely-tech-v1](technical-diagram-style.md) 仅在用户指定该风格或维护旧图时使用，不再是架构图默认。

Tom 插图与 Baoyu 架构图可以同篇使用。全篇统一术语和关系含义，每个图族内部统一画风，不把 Tom 加到每个结构图上，也不把两套背景、字体和画幅强行合并。

## 规划与开始绘制

梳理每张图的：放置位置、读者问题、核心元素、关系、布局、短标签、事实依据和输出位置。既要说“图里有什么”，也要说“怎样把关系画出来”；例如实体图需要实际节点和边，树形图需要分叉。

用户仅要求规划或“先别画”时交付这些内容。已经要求生成或完整配图时，规划作为制作准备，随后直接生成，不另等一次确认。只画一张时不必先制作全篇配图表。

## 真实素材与数据

**截图**：选取能证明结论的实际界面，保留状态和必要上下文；不把设计稿或生成插画当运行结果。裁掉无关区域，处理不宜公开的姓名、头像、凭证、内部地址和业务数据；优先使用合适的测试数据。打码必须完整，不能改变所证明的行为。

**GIF 或视频**：保留操作起点、关键交互和结果，剪掉无关等待；按可读性决定时长、尺寸和帧率。任务包含上传时，在目标平台预览中验证动画确实播放；仅交付本地文件时检查本地播放，不额外发布。平台不支持动画可改用关键帧或受支持的视频格式，不拉伸预览图冒充原件。

**日志与 Trace**：选取错误起点、关键调用和根因，标清时间顺序及错误层。长日志优先用文本代码块，清除不宜公开的凭证和业务信息，不改动决定结论的数值与顺序。

**数据图**：标明指标、单位、数据来源、样本量、环境与时间窗口；对比使用一致口径。截断坐标轴需明确说明。没有数据时不给出伪造曲线或精确百分比。

## Tom 插图与封面

正文插图采用 [Tom 配置](tom-illustrations.md)，从正文选一个明确判断，让 Tom 的动作解释它。角色已由用户指定，不能省略参数后回落到 Visual IP 的 Xiaohei 默认。具体身份、构图和检查读取该 skill 的 Tom 参考；插图不代替真实运行证据或承担密集的架构标签。

封面围绕文章主题保留一个视觉重点，按用户指定或实际平台槽位确定比例。平台未知且只需草图时选合理画幅并说明；精确交付所需尺寸缺失时再询问。标题需在缩略尺寸下可读，不把复杂正文图拉伸成封面。封面请求不意味着上传或发布。

## 阅读与放置

- 比较多条接入路线时，共用总览图可放在对应子章节之前，再分别解释；各路线的独立架构图放在对应小节。用户要求每条路线配图时逐项落实，不用一张泛化示意图替代。
- 图片放在读者首次需要理解该关系的位置。用相邻正文或图注交代观察重点和结论，不强制每张图前后各加一句模板话。
- 图内只保留必要的短标签，长解释回到正文。组件、状态、术语和大小写与文章一致。
- 画幅按内容和所选风格决定，不在本文件另设统一比例。截图、图表、时序和封面尤其不应强行同宽高比。
- 查看完整图片，再按文章显示宽度检查文字、留白和主次。不能只看放大原图；过密时拆图，不靠缩小字装下所有细节。
- 同一图中颜色和线型含义一致，并用文字、形状或图例辅助区分。调用或数据流标明方向，实体关联可以使用无向边。

## 保存与引用

使用用户指定的文章资产目录；没有指定时可用文章旁的 `assets/<article-name>/`。按正文顺序编号并使用可辨认的文件名，例如 `01-evolution.png`、`01-evolution-prompt.md`、`02-retry-sequence.svg`。

源文件按实际工具保存：Tom 与 Baoyu 生成图保存原始位图和完整提示词，不将位图包装成 SVG 冒充可编辑图；用户要求可编辑工程时保存对应绘图源、主题和渲染方式。不同版本使用新文件名，用户明确要求覆盖时再替换。

翻译或重绘来源图表时，简短标明“中文译制”或“据原图整理”，不能把加工图说成官方原始截图。来源链接按语言风格中的引用规则处理。

文章内使用能随文章迁移的资源路径，并验证图片可读取。对话交付使用应用支持的绝对路径或链接。Alt 文本描述图片表达的关系，不只写文件名。尚未提供实际图片时不保留“如下图”的空占位。

## 配图检查

- 图中的关键关系、顺序和结论有依据；简化没有改变机制，样图没有被当作项目证据。
- 标题与标签逐字核对；节点、箭头、分组没有遗漏、反转、遮挡或裁切。
- 真实素材没有泄露不宜公开的信息，数据和 GIF 已按上文验证。
- 图片与正文的用词、观察重点和结论一致，实际资源可访问。

只检查与本图职责相关的项目。涉及实现的结构图按内容规范核对语义，Tom 和 Baoyu 分别按自身指南修订生成错误，不套用另一图族的默认角色或风格。
