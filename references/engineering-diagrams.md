# 架构与工程结构图：内容与关系

用于需要逐项对应真实实现的技术图，只负责技术语义，不选择绘图工具。默认按 [文章配图指南](article-visuals.md) 使用 `baoyu-infographic / craft-handmade`；内容精确性不触发另一套 SVG 风格。用户明确要求可编辑文件或旧风格时再走对应工具。

## 共同准备

先从代码、接口、设计或用户材料中列出参与对象、每个对象在本图的职责、连接的发起方和接收方、核心数据及影响结论的边界。无法确认的设计关系明确标成假设；不要画成已实现事实。

每张图围绕一个问题确定粒度。只保留影响主线的正常路径和关键失败条件；次要细节移到局部图或正文，不能为了稀疏而删除决定结论的步骤。

## 架构与部署

- 选择上下文、服务、内部组件或部署中的一个主要层级。确需跨层时用明确的包含关系，不把用户、Pod、Java 方法和数据库字段当同级对象。
- 组件用真实名称，框内保留名称和必要职责；调用边标动作或数据。协议只有影响设计时才标注。
- 容器表达实际系统、运行或归属边界；部署图区分进程、节点、网络区与第三方基础设施。
- 主链路清楚，依赖方向有依据；不以对称布局暗示双向调用，也不让数据库主动推送，除非确有订阅或回调。

## Pipeline 与流程

- 节点表示动作或处理器，连接表示输入输出及顺序。文档、数据库等形状仅在对应对象确实出现时使用。
- 判断条件放在菱形或分支标签中；不要把每次方法调用都画成判断。
- 对与文章相关的转换、提前消费、旁路、回归主链路、打断和取消明确表达。
- 重试标注触发条件和停止条件；错误或超时如何结束或恢复，按真实实现表示。

## 时序

- 参与者横向排列，时间从上到下，每条消息占独立行。区分请求、返回和异步发送，不能用双向箭头代替整个调用过程。
- 用 `alt`、`opt`、`loop` 或工具中等价结构表示互斥、可选和循环，并注明条件。只保留当前用例需要的参与者和异常分支。
- 若实现需要用户确认，画出实际参与动作；如果没有确认流程，不额外创造一个。
- 打断、并发和超时用例过于复杂时拆成独立图，不与无关业务流程混画。

## 状态与生命周期

- 节点表示当前状态，边表示触发事件与条件。步骤名如“发送请求”不是状态名。
- 核对初始、终止、拒绝、失败、超时、撤销和重试等与该对象有关的状态；不存在的状态不为完整性补齐。
- 正文涉及刷新、重连或服务重启时，交代状态由谁保存、是否恢复，避免图上循环暗示无条件可重试。

## 数据与信任边界

只展开本图需要解释的数据类别、转换、外发位置、凭证传递、权限判断与写入位置。

- 包含边界与信任边界标清名称。不要把语言、颜色或框的视觉分区当成实际安全隔离。
- 标数据类别与凭证名称，不放真实 Token、Cookie 或不宜公开的业务数据。
- 持有 Token 不等于已通过资源授权；恢复身份、校验权限和执行业务写入按实现分别表达。
- 涉及文档、网页或聊天内容作为模型输入时，若其可信程度影响方案，区分数据内容与系统指令。
- 人工确认、权限拒绝和下游不可用只在真实设计且影响论点时出现。

## 交付前核对

沿实际用例从输入走到结果，逐条对照参与者、顺序、数据、条件和运行边界。结构要求写进 Baoyu 提示词，成图后再次逐项核对；过密时拆图，不能为了减少文字丢掉关键条件。视觉检查通过不能代替实现核对。
