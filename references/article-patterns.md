# 按文章类型选择结构

本文件提供可选的组织方式，不是章节模板或交付清单。只选能服务当前问题的部分；语气、事实和任务范围由 [主文件](../SKILL.md) 路由。

## 调研与落地历程博客

适合整理作者已做过的调研、尝试与落地经历。默认先写“背景”：最近在研究什么、参考过哪些产品或框架、自己的需求是什么，再交代本篇范围或系列安排。只采用已确认的经历，不补时间、产品体验或实验结果。

主线围绕目标、候选路线、选择理由、实际接入与使用感受推进。重点写“我为什么这样选、想做到什么、做下来遇到什么”，不扩成评测规程或功能说明书，也不按查资料的时间逐项记流水账。比较维度取自实际需求；主观听感写成个人体验，不推成所有实现的普遍结论。

总结保留认识变化、踩坑和目前判断。已经做过的其他部分，只是本篇未展开，不能写成“这一阶段尚未实现”；下一篇安排按用户确认的进度表述。系列各篇围绕一个主题独立成文，例如“Voice Agent 实践与落地（一）——模型接入”，不自动增设总篇章。

## 业务实战 / 故障复盘

适合已有业务过程、故障材料或验证记录的文章。

可以从现象与影响进入，沿证据解释哪些假设被排除、原因如何定位，再介绍修复选择和验证结果。失败路径、回滚、监控等内容，只展开影响本次结论的部分。

## 原理拆解 / 源码学习

适合协议、组件、算法和运行机制。

从一个具体疑问确定范围，必要时先给结构总览，再沿数据流或调用关系拆解机制。容易混淆的概念单独说明，最后回到理解这些机制能帮助判断的实际问题。公式、代码或实验按解释需要选用。

## 方案选型 / 观点文章

适合比较候选方案或论证采用与放弃的理由。

先明确共同目标与决定性约束，公平说明各方案原本解决的问题，再按相同维度比较能力、成本和边界。结论可以先提出再论证，也可以从比较中得出；保留会改变选择的条件。

## 方案演进 / 研究型观点文章

适合串联多种技术路径，解释问题如何变化。

每个阶段围绕“原先哪里不够用、这条路线改变了什么、增加了哪些责任”展开，但不要把并行方案写成版本升级。未核实历史先后时，用文章讨论顺序组织；不同方法仍可组合，路线切换也可能来自新的目标或资料形态。

一种可选结构是前半解释机制怎样演进，后半集中讨论选择依据、维护分工或下一步需要验证的问题，避免复述全部方案。

## 项目展示 / 工具开发

适合说明一项工具解决了什么、怎样使用及为何这样实现。

从目标问题进入，先让读者看到使用流程或已有结果，再展开少数影响实现的选择、限制和改进空间。是否附代码、安装命令或接入步骤，由文章用途决定，不自动扩成完整教程。

## 好奇心驱动的科普

适合从一个现象或疑问解释技术。

让读者先知道要解释什么，再拆开机制与直觉的差异。已有的小实验、观察和贴切比喻可以帮助理解；没有实验材料时，直接依据资料推理，不为了结构完整增加一次实验。
